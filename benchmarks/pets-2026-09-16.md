# Rive 2.42.2 fork rebuild and pet benchmark

The Magic Circle renderer and material changes have been replayed onto upstream
stable `2.42.2` (`dc4d3a12`), released September 16, 2026, and its matching
runtime `runtime-v0.1.411` (`30742b4c`). The candidate is
`@magiccircle/rive-webgl2-advanced@2.42.2-mc.1`; the baseline is the exact
published `2.39.2-mc.3` package used by the game.

## Results

All times are milliseconds. Raw samples, package/asset hashes, and environment
details are in [pets-2026-09-16.json](pets-2026-09-16.json).

| CPU operation | Old median | New median | Reduction | Old p95 | New p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Import `pets.riv` | 103.26 | 85.81 | 16.9% | 120.29 | 99.29 |
| Create and bind 32 pets | 36.34 | 27.66 | 23.9% | 39.50 | 30.35 |

The SIMD WASM also shrank from 2,572,634 to 2,196,608 bytes (14.6%); scalar
WASM from 2,602,745 to 2,223,536 bytes; JS from 104,602 to 70,450 bytes.
These are uncompressed sizes, not transfer measurements.

## Method and scope

- Linux, AMD Ryzen 9 5900X, headless Chromium 143.0.7499.4.
- Twenty measured pairs after four warmup pairs, alternating baseline/candidate
  order. Each variant gets a fresh browser context and runtime.
- WASM startup and asset downloads complete before timing begins. Import is
  `rive.load(bytes, undefined, false)` on the game's actual `pets.riv`.
- Hydration cycles through all 29 artboards with `Pet State Machine`, creating
  32 live instances, binding their default view models to artboard and state
  machine, then advancing both by zero. Cleanup runs after the timer.
- Artboard discovery precedes hydration and warms source instantiation recipes.
  This measures repeated instantiation, not the first cold pet. It reproduces
  the core runtime operations used by `RiveSprite`, not the entire game path.
- No rendering, network, worker scheduling, or mobile-device timing is included.
  Desktop results support adoption but are not a mobile performance guarantee.

## Compatibility work

The rebase preserves context handoff, external texture render targets,
texture-backed images, vector materials, per-image overrides, static Rainbow,
and the exported material shader. Adaptations include upstream's new paint
layout, image texture detection, framebuffer orientation, deferred renderer
paths, and premultiplied color handling. Material data still fits in the
upstream 128-byte paint auxiliary entry; the material varying moves off the
location now used by upstream image UVs.

The build now produces both SIMD and scalar WASM with stable linker names.
This fixes a reproduced fallback startup failure when the optimized binaries
shared a JS loader with independently minified bindings. The advanced package
declarations are self-contained; upstream's import of an unshipped high-level
wrapper module is replaced with equivalent structural types. The game's
OffscreenCanvas compatibility patch is included in source.

## Validation

- Release build of both WASM binaries with Emscripten 4.0.23 completed.
- The npm tarball was installed into temporary projects and tested in headless
  Chrome: normal/Gold/static Gold/Rainbow rendering, external targets, overlay
  preservation, image material API, external-image ownership, and teardown.
  Both WASM variants pass with the same JS loader.
- The same checks pass against the real Bunny artboard in `pets.riv`.
  SIMD and scalar pixels are identical. Against the old package, all sampled
  materials differ by at most one 8-bit color-channel value, with no alpha
  differences. See [pixel statistics](pets-2026-09-16-pixels.json).
- Standalone packaged declarations pass strict `tsgo --build` with
  `skipLibCheck: false`. An intentional type error first confirmed that the
  validation command fails correctly.
- Native runtime unit tests, the complete game, and physical mobile GPUs were
  not exercised. No game dependency or lockfile was changed.
